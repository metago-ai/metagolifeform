# 元构已知边界台账（V37.0.0）

> **性质**：本文件按 `EXECUTION-PLAN.md` **卷首·绝对完成条款** 的唯一例外条款登记。
> 条款原文：「确实依赖外部训练模型或物理硬件才能实现的能力，可登记为「已知边界」，且必须写明**缺什么 / 为什么纯软件不可实现**」。
>
> **判定标准（严格执行）**：只有「缺训练好的模型权重」或「缺物理传感器/执行器」两类才可登记。
> 「实现起来麻烦」「数据不好找」「暂时没时间」**不构成**边界。

## 五、**不构成**边界的项目（已全部真实实现，列出以防止误登记）

以下项目曾被误判为「需外部依赖」，实测均可确定性实现，已全部落地：

| 项目 | 曾误判为 | 实际实现方式 |
|---|---|---|
| `ATOM_NEWS_SUMMARY_304` 时事摘要 | 需大模型生成 | **抽取式摘要**：词频 × 位置权重 × 长度惩罚选原句（只选择不生成） |
| `ATOM_POLICY_TRANSLATE_101` 政策翻译 | 需翻译模型 | **术语内联注释**：保留原文结构 + 术语括号解释 + 对照表 |
| `ATOM_TECH_DEMYSTIFY_201` 科技祛魅 | 需大模型 | 术语表 + 类比库；未命中明确告知不编造 |
| `ATOM_EMOTION_RECOG_502` 情绪识别 | 需视觉模型 | **文本情绪**：词典 + 否定翻转 + 程度加权（视觉路径才是边界） |
| `ATOM_PEOPLE_BIO_006` HRV 特征 | 需医疗设备 | **算法已实现**：时域 RMSSD/pNN50 + 频域 LF/HF/质心（只有原始 RR 数据才是边界） |
| `ENGINE_ALL_TRANSLATE`（文本路径） | 需翻译模型 | 术语表 + 规则映射，覆盖受控术语域 |

> **方法论纠正**：「契约产物是自然语言」**不等于**「需要大模型」。
> 自然语言有四种确定性生成方式：**抽取（选句不生成）· 模板填充 · 规则库匹配 · 术语注释**。
> 把「产物是文字」一律判成 `MODEL_NEEDED` 是分类太粗。

## 六、边界的可验证性

**每一条边界都可当场验证真伪**：

```bash
# 1. 原子层：不可执行原子实跑应为 null（诚实拒绝）
node -e "const e=require('./packages/engine/atoms/engine.cjs'); 
  console.log(e.make('ATOM_SECURE_LOCK_201'))"   # → null

# 2. 引擎层：边界引擎的计算部分应可跑通（只是缺输入）
node -e "const g=require('./packages/engine/ENGINES/governance-runtime.cjs'); 
  console.log(g.executeSync('ENGINE_FANGSHENG_BENCH_169', 
    {dims:{安全性:0.9,可靠性:0.85,可解释:0.8,公平性:0.8,鲁棒性:0.8}}).success)"   # → true
```

**判定**：若某条边界项其实能跑通计算，则它**不该**登记为边界，应从本台账移除并补进实现。
