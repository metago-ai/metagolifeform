## 四、最重要的一条：断言强度守卫

**事故**：我在同步脚本时写了 `shutil.copy2(MB/xxx, H/xxx)`，而 `metago-build` 下的 `mcp-tools-semantic.cjs` 是**更旧的副本**。结果 R141 强化的 4 条断言（查数值）全部被覆盖回弱版（只查结构），且三个副本都变成弱版。

**怎么发现的**：`selftest_semantic_teeth.mjs` 报「有牙自检：9/11，`normalize_coupling` 两条漏过」。

**如果没有那条元断言，这个回退会一直潜伏**——所有检查照样全绿，但检测器已经瞎了。

**修法与防复发**：

1. 恢复 4 条强断言（`build_coupling_matrix` 查对角/对称/权重、`normalize_coupling` 查极值、`identify_*_pairs` 查阈值）
2. 建 `assertion_strength_guard.mjs`：检查 6 个特征标记存在，任一缺失即 FAIL
3. 接入回归
4. 模板登记为补丁 P29

**这条守的是「我自己的修复不会被我自己的操作覆盖」。**

## 十一、第五轮复检后的补修（time_decay 与「类型正确 ≠ 语义正确」）

### 复检指出的问题：核实成立

	ime_decay_cooccurrence 的 schema 缺 item1/item2，而算法签名是
	imeDecayCooccurrence(events, item1, item2, halfLifeMs, now) —— 必须知道「算哪两个项之间的共现」。

**但复检给的是「schema 缺两个属性」，我查到的是适配器有三个硬编码：**

`js
return [evs, at[0], at[1], hl, Date.now()];
//           ↑忽略 a.item1  ↑忽略 a.item2  ↑硬编码当前时间
`

**第三个才是最致命的**：
ow = Date.now()（约 1.79e12 毫秒），而 example 的 timestamps 是 0/100/200
→ ge ≈ 1.79e12，weight = 0.5^(1.79e12/5000) ≈ 0 → 	otal 与 weighted 都是 0 → score 兜底为 0。

**所以只加 item1/item2 到 schema 不够，必须同时修适配器。**

修完实测：

`
items=[[a,b],[a,b],[b,c]], timestamps=[0,100,200], item1=a, item2=b, halfLife=5000
→ score = 0.662035     （我手算 0.6622，一致）
item1=a item2=c（无共同事件）
→ score = 0            （正确）
`

**顺手发现同类问题**：cooccurrence_frequency 的算法也要 item1/item2（适配器能从 items 推导，

## 十二、第六轮复检后的补修（函数桥接 preset 死代码）

### 复检的核心发现：核实成立，但根因比它说的更深

复检说：「L4 路径缺函数桥接，`tool-registry.js:662` 直接 `executeAlgorithmSync(targetId, input)`」。

**实测发现：不是 L4 缺桥接，而是桥接层对 preset 名称本身失效。**

```js
METAGO_FN_PRESETS = { 'Math.random': ..., 'random': ..., 'identity': ..., ... }   // preset 里明明有
METAGO_FN_SRC_RE  = /^\s*(async\s+)?(\(|[A-Za-z_$][\w$]*\s*=>|function\b)/     // 'Math.random' 不匹配

// metagoCoerceFn 的判断顺序：
else if (typeof v === 'string' && METAGO_FN_SRC_RE.test(v)) src = v
if (src === null) return value;      // ← 不匹配 RE 就原样返回字符串，永远走不到 preset
```

**`'Math.random'` 含点号，不符合 RE 的 `(… / x=> / function` 形式 → `src` 保持 null → 原样返回字符串
→ 算法内 `rng()` 崩 → `rng is not a function`。**
**所以 `METAGO_FN_PRESETS` 里的 `'Math.random'` / `'random'` / `'identity'` 全是死代码。**

**实测四路对照（ALG_T1_M_001 generateNovelIdea）：**

| rng 形式 | 修前 | 修后 |
|---|---|---|
| 裸字符串 `"Math.random"` | ❌ rng is not a function | ✅ success |
| `{__fn__:"Math.random"}` | ✅ | ✅ |
| `"() => 0.5"` | ✅（匹配 RE） | ✅ |
| 真函数 | ✅ | ✅ |
| `"random"`（preset 别名） | ❌ | ✅ |

**影响面比复检说的大**：不只 L4 路径，**注册表直调同样失效**。

**修法**：把 preset 查找**提前到 RE 判断之前**。

### 复检说「verify-package.cjs 仍 16 条断言，无 examples 可执行性」——成立，已补 K17

新建 `verify_examples_exec.mjs`：**全 57 个工具**（含 L4 的 20 个）按各自 `examples[0]` 通过 MCP 工具层实调。

**这补的是我此前的真空档**：`audit_by_examples.mjs` 只覆盖 30 个 L3 工具，
**L4 的 20 个从未做过 examples 实调** —— `creation_create` 就是从这个缝里漏过去的。

**结果**：56 OK + 1 LEGIT_EMPTY = **57/57 通过**。

### 我在这轮修的过程中发现的两个更深问题

**问题 A：P19 补丁模板会让 preset 修复回退**

我修的是实体 `registry.js`，但 P19 补丁注入的是 `patches/r141-positional.tpl` 这个**代码块模板**。
模板里还是旧版 `metagoCoerceFn` → **重装后 P19 注入旧模板，preset 死代码原样回来。**

修法：
1. 模板同步换成新版（4,106 → 4,671 B）
2. 加版本标记 `R142-PRESET`
3. **P19 的 `--check` 逻辑从「有没有注入」改为「注入的是哪个版本」** —— 实体缺 `R142-PRESET` 就报「代码块是旧版，需重新注入」

**问题 B：验收本身的偶发失败（8 次验收 2 次失败）**

抓到偶发项：`对抗审查 A8/A9/A10`。
根因：A9 用 `spawnSync` 调子脚本时 **`maxBuffer` 默认 1MB，927 条算法的输出会超 → 拿不到 stdout
→ 声称数变成 -1 → 判「覆盖数不符」**。

修法：4 处 `spawnSync` 统一改用 `RUN()` 包装（`maxBuffer: 32MB` + 重试一次）。
实测：**连续 12 次全部通过**。

**同时给 `final_acceptance.py` 加了「失败项自动留证」**（写入 `final_acceptance-fail-log.jsonl`），
这样下次再出现偶发，能直接追溯到具体项而不是靠猜。

### 一个我保留未改的观察

`identity` preset 用在 `generateNovelIdea` 的 rng 上会报 NaN —— 因为 `identity(x) = x`，
被当随机数调用时无参数 → undefined → NaN。

**这不是 preset 的缺陷，是「用错预设」**：rng 期望的是返回 0–1 的函数，
而 identity 是恒等函数。preset 的行为是对的，语义要用对。
