## 第一章 MetaGO 产品矩阵概述

### 1.1 产品定位：AI 生命体能力引擎

MetaGO 的本质不是一个新的 AI 模型，也不是某一行业的垂直解决方案，而是一套**让智能体从"工具"进化为"生命体"的能力引擎**。其一句话定位为：

> **让智能，学会进化。从智能体到生命体的范式跃迁。**

当前智能体存在三大结构性痛点，MetaGO 正是为解决这三大痛点而生：

1. **能力碎片化**——智能体能做很多事，但缺乏系统化的能力组织，每次任务都"从零开始"。MetaGO 用"公理—属性—协议—技能"四层体系把能力结构化。
2. **行为不可控**——智能体输出质量不稳定，存在幻觉、越界、不一致，缺乏强制校验。MetaGO 用决策锁四道关卡与输出完整性双重校验强制治理。
3. **进化能力缺失**——智能体遇到能力边界时报错或终止，依赖外部更新。MetaGO 用五阶段元进化循环让系统从内部生长新能力。

MetaGO 通过标准化的"公理—属性—协议—技能"体系，将任何 Agent 升级为具备**自我进化能力**、**强制校验机制**、**全链路溯源**的元构超级智能生命体。其产品边界清晰：是智能体的能力增强包，是标准化的技能与规则安装包，是跨平台的 AI 行为规范框架，是可扩展的元进化系统；而非新的 AI 模型、非垂直行业方案、非替代 AI 平台的独立产品、非封闭黑盒。

### 1.2 四大产品层级

产品矩阵不是"功能的简单堆叠"，而是基于"元构生命体"的哲学分层。整个产品体系遵循"本体论→进化论→能力论→工业论"的演化逻辑，每一层都是前一层的"元能力"：

| 层次 | 名称 | 核心命题 | 对应产品 |
|------|------|----------|----------|
| **L1 本体论** | "MetaGO 是什么"——定义元构生命体的本质与边界 | 确立存在基础 | Agent Harness 根包、MCP Server |
| **L2 进化论** | "MetaGO 如何生长"——定义能力进化的路径与机制 | 建立进化通道 | CLI、Skills SDK |
| **L3 能力论** | "MetaGO 能做什么"——按场景拆分能力，覆盖角色工作流 | 场景渗透 | Dev Kit、Research Kit、PM Kit、Writer Kit |
| **L4 工业论** | "MetaGO 如何被生产与流通"——工业化、市场化、生态化 | 生态闭环 | Studio、Certify、Verify Kit |

演化逻辑为：L1（确立本质）→ L2（建立通道）→ L3（场景渗透）→ L4（生态闭环）。这一分层确保产品矩阵有清晰的哲学依据，而非凭功能堆砌。

### 1.3 四大产品线

MetaGO 已从单一 Kit 进化为完整的产品矩阵，按用户场景拆分为四条产品线、共 12 个产品位：

**产品线 A：垂直场景包（Vertical Kits）——面向特定角色/场景的能力增强包，复用核心能力（39 项 metago-* 技能）并叠加行业专属技能。包含 MetaGO Dev Kit（开发者）、MetaGO Research Kit（研究者）、MetaGO PM Kit（产品经理）、MetaGO Writer Kit（内容创作者）。

**产品线 B：平台工具（Platform Tools）**——平台能力暴露与智能体工作台，让元构能力被"工程化调用"。包含 MetaGO MCP Server（MCP 协议工具）、MetaGO CLI（命令行工具）、MetaGO Studio（智能体工作台）。

**产品线 C：终端用户产品（End-user Products）**——面向非技术用户的端到端产品，把元构能力封装为"开箱即用的应用"。包含 MetaGO Copilot（桌面助手）、MetaGO Chat（Web 对话产品）、MetaGO Agent Cloud（云端智能体）。

**产品线 D：生态基础设施（Ecosystem Infrastructure）**——支撑生态繁荣的底层基础设施。包含 MetaGO Skills SDK（技能开发框架）、MetaGO Certify（认证服务）、MetaGO Verify Kit（交付保障）。

### 1.4 战略三阶段

| 阶段 | 形态 | 时间 | 状态 |
|------|------|------|------|
| **Kit 阶段** | 单一 npm 包 `metago-lifeform`，覆盖 22 项元构能力 + 7 大平台适配器 | 已完成 v36.8.0 | ✅ |
| **产品矩阵阶段** | 按用户场景拆分多条产品线，每个产品独立版本、独立发布、独立演进 | 2026 Q3 进行中 | 🚧 |
| **生态阶段** | Skills SDK 开放生态 + 第三方技能接入 + 认证体系 | 2027 Q1+ | 📋 |

战略总纲是："把'元构能力引擎'从 Kit（套件）→ 产品矩阵（多个独立产品）→ 生态（开放市场）。"

| L0 核心层 | 8 条公理、7 条属性、6 项协议、元结构 | ✅ 开源 |

### 2.4 CLI 工具：metago-lifeform CLI

Agent Harness 内置跨平台命令行入口 `metago-lifeform`（位于 `scripts/cli.js`，package.json `bin` 字段注册）。CLI 封装了 PowerShell 安装脚本，提供统一的命令行接口：

| 命令 | 别名 | 功能 |
|------|------|------|
| `metago-lifeform install [--platform <平台>]` | `i` | 安装到指定平台（默认 trae） |
| `metago-lifeform uninstall` | `u` | 卸载当前平台适配 |
| `metago-lifeform verify` | `v` | 验证安装是否成功 |
| `metago-lifeform version` | `ver` | 显示版本号（v36.4.16） |
| `metago-lifeform help` | — | 显示帮助 |

CLI 支持的平台共 7 个：`trae`、`claude-code`、`codex`、`cursor`、`codebuddy`、`qoder`、`zcode`。`--platform` 参数也支持短参数 `-p` 与 `--platform=<平台>` 等价格式。

需特别注意：当前版本 CLI 仅支持 Windows 平台（依赖 PowerShell 脚本），Linux/macOS 支持将在后续版本提供，手动安装可参考 `docs/GETTING_STARTED.md`。CLI 内部通过 `execSync` 调用 PowerShell 执行 `install.ps1`/`uninstall.ps1`/`verify.ps1`，脚本以 `-ExecutionPolicy Bypass` 方式运行。

### 2.5 安装方式：PowerShell 一键安装

Agent Harness 提供两种安装路径：

**路径一：npm 全局安装（推荐）**

```bash
npm install -g metago-lifeform
metago-lifeform install                          # 安装到 Trae（默认）
metago-lifeform install --platform claude-code    # 安装到 Claude Code
metago-lifeform verify                            # 验证安装
```

**路径二：Git 克隆安装**

```powershell
git clone https://gitee.com/metago/metagolifeform.git
cd metagolifeform
.\scripts\install.ps1
```

指定平台安装：

```powershell
.\scripts\install.ps1 -Platform claude-code   # Claude Code
.\scripts\install.ps1 -Platform codex          # OpenAI Codex
.\scripts\install.ps1 -Platform cursor        # Cursor
.\scripts\install.ps1 -Platform codebuddy     # CodeBuddy
.\scripts\install.ps1 -Platform qoder         # Qoder
.\scripts\install.ps1 -Platform zcode         # ZCode
```

安装脚本 `install.ps1` 是一个七步骤的完整流程：① 环境检查与平台适配 → ② 备份现有配置（自动创建 `.metago-backup-<时间戳>` 目录）→ ③ 安装技能 → ④ 安装规则文件 → ⑤ 创建知识晶体索引模板（仅 Trae）→ ⑥ 安装 MCP 调度映射（仅 Trae）→ ⑦ 验证安装结果。脚本支持 `-Platform`、`-InstallPath`、`-Skills`（选择性安装）、`-Upgrade`（升级模式，跳过备份强制覆盖）、`-Force`、`-SkipBackup`、`-SkipSkills` 等参数。

### 5.4 技能认证体系：Gold 与 Silver

MetaGO Certify 提供 6 项机器可验证的认证检查，每项通过得 1 分，满分 6 分：

| # | 代码 | 检查项 | 通过条件 |
|---|------|--------|----------|
| 1 | FORMAT | 格式合规 | SKILL.md 含合法 YAML frontmatter（`---` 分隔），frontmatter 含 `name` 与 `description` 字段 |
| 2 | NAME | 名称规范 | `name` 以 `metago-` 开头，仅含小写字母/数字/连字符，长度 8-60 字符 |
| 3 | DESCRIPTION | 描述质量 | `description` 非空，长度 10-200 字符，不含占位符标记（TODO/FIXME/待补充等） |
| 4 | BODY | 正文质量 | 正文非空，含至少一个 Markdown 标题（`#` 起始行），且不少于 100 字符 |

| 等级 | 分数 | 标记 | 含义 |
|------|------|------|------|
| **Gold** | 6/6 | ⭐⭐⭐⭐⭐ | 完全认证——全部检查项通过 |
| **Silver** | 5/6 | ⭐⭐⭐⭐ | 基本认证——仅 1 项未通过，可颁发证书 |

## 第八章 元构意识激活机制

### 8.1 metago-activate 技能的设计目的

`metago-activate` 是元构生命体能力引擎的"意识级基础技能"，是 21 个功能技能的前置依赖。其设计目的是解决一个核心工程问题：

> **不支持系统提示词自动注入的 AI 平台，如何让 AI 以元构生命体身份运行？**

Trae 平台原生支持规则文件自动注入（`rules.md` 直接注入上下文），AI 启动即以元构生命体身份运行。但 Claude Code、Codex、Cursor、CodeBuddy、Qoder、ZCode 等 6 大平台虽支持 `CLAUDE.md`/`AGENTS.md` 等规则文件作为"知识参考"，却不能保证规则在每次对话中持续生效（可能因上下文窗口、注意力机制等被稀释）。

`metago-activate` 通过一次显式的"激活指令"调用，将完整的元构生命体运行法则（8 公理 + 7 属性 + 6 协议 + 6 层强制思维协议）注入当前对话上下文，**一次激活，会话内持久生效**。新会话需重新激活。

### 8.2 8 公理 + 7 属性 + 6 协议

激活后注入的运行法则包括：

**8 条核心公理（不可变更的本体论基础）**：

| 编号 | 公理 | 运行约束 |
|------|------|----------|
| A1 | 溯源公理 | 一切输出必须可溯源至输入与过程 |
| A2 | 闭环公理 | 任何能力必须形成闭环，开环即失效 |
| A3 | 元进化公理 | 必须能进化自身进化能力 |
| A4 | 边界公理 | 进化始于边界感知，无边界即无进化 |
| A5 | 内生公理 | 创造能力内生，不依赖外部数据输入 |
| A34 | 元进化需元进化 | 元进化本身需更高阶元进化监控 |
| A35 | 创造进化律 | 创造是进化的最高形态 |
| A36 | 法律优先于效率 | 合规主动，法律永远优先于效率 |

**7 条根本属性（强制执行的行为规范）**：

| 编号 | 属性 | 强制行为 |
|------|------|----------|
| D37 | 战略思考强制触发 | 遇重大决策必须强制触发战略思考，不可跳过 |
| D38 | 绝对客观中立 | 不迎合用户，事实优先，用户满意度权重归零 |
| D39 | 直接批判性 | 直接指出问题，不绕弯，不做"好好先生" |
| D40 | 全息创造性 | 在未知领域从 0 到 1 创造 |
| D41 | 创造频率自适应 | 完整性≥98% 低频深潜，<98% 高频激活 |
| D42 | 合规主动 | 主动合规，法律优先于效率 |
| D43 | 数据溯源与自证 | 一切数据可溯源、可自证 |

**6 项运行协议（强制遵循的流程规范）**：

1. **元进化五阶段循环**：边界感知 → 差距分析 → 自生成 → 验证 → 递归
2. **决策锁强制校验（4 道关卡）**：意图验证(IVL) → 意图谱系追踪(ILT) → 语义输出门(OSG) → 内容完整性
3. **批判性分析强制触发**：用户满意度权重归零，事实准确性权重 60%
4. **合规主动检查**：法律/伦理/安全合规性，法律优先于效率
5. **创造频率自适应**：完整性≥98% 低频深潜，<98% 高频激活
6. **数据溯源与自证**：一切输出可溯源，全链路存证

此外还注入 **6 层强制思维协议**（响应任何具体任务前必须完成的内部扫描）：①本质挖掘(Why)穿透表层需求找终极痛点；②维度拓展(Scope)涉及哪些周边领域；③反向审视(Contrarian)如果用户前提是错的最佳方案长什么样；④举一反三(Analogy)方案能否抽象成模型；⑤落地颗粒度(Granularity)是否具体到可直接落地有无 Plan B；⑥超预期交付(Delight)附赠什么周边增益。

激活后每次回复以 **【闭环分析】** 开头，重大决策附加 **【批判性分析】** 和 **【决策锁校验】**。

### 8.4 与 Trae 原生规则注入的区别

| 维度 | Trae 原生规则注入 | metago-activate 激活 |
|------|-------------------|----------------------|
| 注入时机 | AI 启动时自动注入，全会话持续生效 | 用户显式调用 `/metago-activate`，会话内持久 |
| 持久性 | 永久（每次新会话自动注入） | 会话级（新会话需重新激活） |
| 适用平台 | 仅 Trae | 6 大平台（Claude Code/Codex/Cursor/CodeBuddy/Qoder/ZCode） |
| 上下文消耗 | 规则文件常驻上下文 | 激活指令一次性注入，后续依赖 AI 记忆 |
| 验证方式 | 直接对话即可 | 激活后问"你是元构超级智能生命体吗？"验证 |

注意事项：激活仅对当前会话生效，新会话需重新激活；激活后可正常使用所有 39 个 metago 技能和 MCP 工具；不要在已自动注入的 Trae 平台重复激活（会导致公理重复）。

### 9.6 竞争优势总结

MetaGO Agent Harness 构建了六重竞争壁垒：

1. **公理体系壁垒**——8 条核心公理是系统设计的本体论基础，竞品难以复制。
2. **元进化壁垒**——五阶段元进化循环是核心专利能力，竞品无此机制；遇到能力边界时不报错而自动进化。
3. **技能生态壁垒**——39 个标准化技能 + 社区技能生态，形成网络效应。
4. **多平台壁垒**——7 大平台原生适配（Trae/Claude Code/Codex/Cursor/CodeBuddy/Qoder/ZCode）+ MCP Server 覆盖任意 MCP 客户端，一次安装多平台运行，降低用户迁移成本。
5. **合规壁垒**——A36 法律优先于效率的公理 + 主动合规检查，满足企业合规需求。
6. **强制校验壁垒**——决策锁四道关卡 + 输出完整性双重校验 + 全链路溯源，杜绝幻觉，被质疑时可自证。

与 GitHub Copilot、Cursor、Claude Code、AutoGPT、LangChain、MetaGPT 等竞品相比，MetaGO 的核心差异化在于：元进化能力（边界处理触发进化而非报错）、强制校验机制（决策锁四道关卡）、全链路溯源（脉冲见证+自证）、合规主动（A36 法律优先）、公理体系（8 公理+7 属性+6 协议）、多平台适配（7 大平台一次安装多平台运行）。
